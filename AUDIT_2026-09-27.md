## 2. The shared-search speed fix: **NOT committed anywhere**

Searched every branch. `kira_commands.py` contains **no** reference to
`search_shared_knowledge` on `zakaria`, on MED, or on `main`. The fix that was
tested on the Windows PC was never committed or pushed. It exists only in that
PC's working tree (if still there at all).

Verified slow path as it stands on `zakaria` today (`/api/command` with
"search shared knowledge for X"):

1. `kira_api._handle_command` → `kira_commands.process_command`.
2. `backend.parse_simple_command` (kira_voice_agent, ~line 1035–1100) returns
   `{"action": "search_shared_knowledge", "query": ...}` — parsing regexes exist
   and work.
3. `process_command` falls into the generic action path:
   `backend.execute_action(parsed)` → `kira_voice_agent.search_shared_knowledge`
   (line 2562) which calls `speak()` **up to 4+ times synchronously** (one intro
   plus one per result, line 2605–2615) before returning `True`.
4. Then `languages.ensure_reply_language` may call **Ollama** to translate
   `build_reply`'s generic text.
5. Only after all of that does the HTTP response return.

So the bug the fix addressed is fully present in the repository: backend speech
and a possible model call block the HTTP response. The UI meanwhile has its own
speech path (`/api/tts` + browser playback), so the backend speech is not only
slow — it is redundant for UI-originated requests.

**Action item: re-implement the fix in `kira_commands.process_command` (early
route before the generic action path) and commit it this time, with a
regression test.**

## 3. Client-disconnect crash (WinError 10053)

Two places write responses to sockets with no disconnect handling:

- `kira_api.py` `_send_json` (line 67–75): `self.wfile.write(body)` — raises
  `ConnectionAbortedError` / `BrokenPipeError` when the window is closed
  mid-request. `BaseHTTPRequestHandler` then logs a traceback.
- `kira_ui.py` `_proxy_api` (line ~113–148) and `_json_error`: same pattern.
  This is the exact spot the reported `WinError 10053` comes from — the proxy
  waits up to `api_timeout = 125` s for the backend, and if the user closed the
  window, the write back fails.

Neither is data-loss (the client is gone), but the traceback noise looks like a
crash and can mask real errors. Fix: catch
`(ConnectionAbortedError, ConnectionResetError, BrokenPipeError)` at the write
sites, log one quiet line, and return. Never retry, never re-raise.

## 4. Result-shape and speech/execution coupling (current state)

- `process_command` returns ad-hoc dicts: `{"action", "response", "success"?,
  "opened"?, "needs_choice"?, "error"?, "error_code"?, **language metadata}`.
  Shapes differ per path; there is no timing information anywhere.
- Speech coupling inventory (backend functions that `speak()` during
  `execute_action`, i.e. block HTTP responses):
  - `search_shared_knowledge` (worst: multiple sequential speaks) — fixed by item 2.
  - `share_project_knowledge` (speaks status).
  - Task handlers (`speak("Reminder added…")`, task lists, clear-completed…).
  - Various error prompts (mic errors, "I did not understand…").
  These are fine for the **voice** loop (that is its output channel) but wrong
  for the **API** path. The long-term architecture ("tools return data, they do
  not speak") means API-originated calls must reach tool logic that never
  speaks; voice-loop callers add speech on top.
- `BRANCH_CONSOLIDATION.md` confirmed: history-only merges did NOT activate old
  features, and **the API has no authentication** (the guarded-API work from
  `01a0c549` was deliberately not ported). `kira_api` binds `0.0.0.0` by
  default (`DEFAULT_HOST`), while `kira_ui.py` defaults to loopback. Worth
  revisiting later; out of scope for this change.

# Focused first implementation (small, testable)

One branch off `zakaria` (`bc5239d`), four contained changes, no UI files
touched (friend's design untouched by construction):

## Change 1 — Shared-search fast path (re-apply the lost fix)

In `kira_commands.process_command`, immediately after
`parsed = backend.parse_simple_command(cleaned)` resolves an action:

- If `action == "search_shared_knowledge"`: call
  `kira_web.search_shared_knowledge(query, limit=3)`, return
  `{"action": "search_shared_knowledge", "success": True, "response": <text>,
  "elapsed_ms": …, **metadata}` directly.
- No `backend.execute_action`, no `ensure_reply_language` / Ollama call on this
  route. The existing UI already displays the response and speaks it via its
  own TTS path.
- `kira_web.search_shared_knowledge` already returns clean, formatted text and
  handles "not configured" and "no results" cases — reuse as-is.

## Change 2 — Graceful client-disconnect handling

- `kira_api.py`: wrap the socket write in `_send_json` with
  `except (ConnectionAbortedError, ConnectionResetError, BrokenPipeError)` →
  one `logger.debug` line, no traceback, no retry.
- `kira_ui.py`: same guard around the proxy's response write and `_json_error`.
- No behavioural change for connected clients.

## Change 3 — Minimal `ToolResult` convention + timing (template, not big-bang)

- New tiny module `kira_tools.py`: `ToolResult` (dataclass:
  `ok, data, response, error, error_code, elapsed_ms`) with `.to_payload()`
  producing the exact dict shape the API/UI already consume — so existing
  clients see a superset (new `elapsed_ms` key), nothing breaks.
- A `timed_tool(fn)` helper that measures wall time and converts exceptions to
  structured failures.
- Apply it to the shared-search route only, as the template for future tool
  migration. No other handlers refactored yet (deliberately small).

## Change 4 — Regression tests

New `tests/test_shared_search_route.py` (mirrors existing mock-backend style in
`test_languages.py` / `test_pending_fixes.py`):

1. `search_shared_knowledge` route returns the research text as `response`.
2. `backend.execute_action` is **never called** on this route (regression for
   the speed fix — this test fails on today's `zakaria`).
3. `backend.call_ollama` / translation is never called on this route.
4. `elapsed_ms` present and sane.
5. Disconnect tests: `_send_json` swallows `ConnectionAbortedError` (simulated
   `wfile`), same for the UI proxy write.
6. Full existing suite stays green (207 + 64 baseline).
